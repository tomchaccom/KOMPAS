# 디자인 시스템 — 선생님 학생 상세 화면부터

2026-10-29 · 상태: 초안(사용자 확인 전)

## 왜 하는가

선생님 화면에서 학생 한 명을 열면(`teacher.html` 의 `#detail`, `js/ui/teacher.js` 의 `openDetail`)
세 가지가 불편하다고 사용자가 말했다.

- 글자가 작다.
- 항목이 나열식이라 시선이 분산된다. 잘한 점과 방향이 확인은 되지만 한눈에 들어오지 않는다.
- 아래로 갈수록 길어져서 읽기 힘들다.

그리고 UI 수정이 잦고, 만든 UI 가 마음에 안 들 때 고치는 비용이 크다. 화면 조각이 컴포넌트로 분리돼 있지 않아서다.
사용자는 프론트엔드를 잘 모른다. 그래서 만든 사람이 아니라 **고치는 사람이 이해할 수 있는** 구조여야 한다.

## 현재 상태 (읽어서 확인한 것)

- 색·글꼴·그림자 토큰은 `styles.css` 맨 위에 이미 있고 라이트/다크가 있다. 토큰은 새로 만들지 않는다.
- `.btn` `.chip` `.tag` `.mark` `.code` 가 CSS 2~4개 파일에 서로 다른 모양으로 정의돼 있다.
- 버튼류: `.btn` `.pill` `.tbtn` `.mbtn` `.iconbtn`. 라벨류: `.tag` `.badge` `.mark` `.al-tag`.
  카드류: `.card` `.rescard` `.wrapcard` `.sentcard` `.compass-card` `.peercard`. 안내 상자: `.saybox` `.review-box`.
- `el(tag, cls, txt)` 가 6개 JS 파일에, `esc()` 가 4개에 복사돼 있다.
- 학생 상세는 `teacher.js` 589~897행(`openDetail`, 약 310줄)과 `compassCard`(407~560), `levelRecords`(560~589),
  `teacher.css` 의 `.d-*` `.detail *` 규칙이 만든다. 화면 조각을 JS 로 조립한다.
- 저장소 규칙: 번들러 · 의존성 · ES 모듈을 쓰지 않는다. 정적 파일만. `core` / `data` / `ui` 층 경계는 `test/layer.test.js` 가 검사한다.

## 목표

1. **학생 상세 화면을 A안으로 다시 그린다** (아래 "정한 것").
2. **그 화면에서 쓰는 조각을 컴포넌트로 뽑는다.** 한 곳에서 모양을 바꾸면 쓰는 곳이 다 바뀐다.
3. **전·후를 숫자로 보여준다.** 같은 화면을 컴포넌트 이전/이후 코드로 비교한다 — 줄 수, CSS 규칙 수, 중복 정의 수, 한 모양을 바꿀 때 고쳐야 하는 파일 수.
4. 선생님 학생 상세 말고 **다른 화면에서 컴포넌트로 뽑을 코드 후보를 찾아 목록으로 남긴다** (바꾸지는 않는다).

## 하지 않을 것

- 학생 화면(`index` `sentence` `abstract` `review` `make`) 고치기. 이번에는 후보 목록만.
- 새 프레임워크 · 번들러 · 빌드 단계 · npm 의존성.
- 새 색 · 새 글꼴 체계. 기존 토큰 그대로.
- CLAUDE.md 의 금지 목록을 건드리는 표시: 점수 · 순위 · 정답률 · 반 평균 · 소요 시간 · 추천. 요약 카드의 "잘한 점"은 사실 문장이고 칭찬 낱말은 쓰지 않는다
  (말은 선생님이 한다). 학생 화면에 새로 나가는 것은 없다.

## 이런 결과면 실패다

- 화면은 예쁜데 이벤트를 접는 규칙이나 나침반 계산이 달라졌다 (`fold.js` · `_compass.py` 를 건드리면 안 된다).
- 컴포넌트를 만들었는데 호출하는 쪽 코드가 오히려 길어졌다.
- 선생님이 열어서 읽고 고칠 수 없는 구조가 됐다.
- 기존 테스트(`test/smoke.js` `test/robust.js` `playwright` 등)가 깨지거나, 학생 자유 입력이 상세 화면에 안 올라간다.

## 정한 것 (사용자가 정함)

- **배치는 A안.** 맨 위 요약 카드 하나에 "잘한 점"과 "방향(나침반)"을 크게. 아래는 미션별 한 줄씩 접어 두고 눌러서 펼친다. 최근 미션이 위.
- **위에서 아래 순서 (시안 확인함):** ① 요약 카드(잘한 점 + 방향) → ② 선생님이 할 일(방향 겹침 고르기 · 선생님 한마디, 접지 않는다)
  → ③ 미션 기록(한 줄씩 접힘, 최근이 위) → ④ 가끔 보는 것(나침반 자세히 · 레벨 테스트 기록, 접힘). 배치와 글자 크기는 사용자가 시안으로 확인했다.
- **나침반 그림은 새로 만들지 않는다.** `js/core/compass.js` 가 만드는 바늘 · 다각형 SVG 를 요약 카드 안에 그대로 넣는다. 시안의 동그라미는 자리 표시였다.
- **글자를 지금보다 키운다.** (제 추측: 본문 18px 안팎, 이름 30px. 시안 값. 실제 값은 구현에서 조정.)
- **범위: 선생님 학생 상세 화면만 먼저.** 그 뒤에 전체 화면에서 컴포넌트 후보를 찾는다.
- **전·후 비교를 보여준다** (목표 3).

## 제 판단 (사용자가 확인하지 않음)

- 컴포넌트는 `js/ui/` 층에 둔다 — DOM 을 만드는 코드라서. 새 파일 `js/ui/kit.js`(전역 `CC.kit`) 하나와 `kit.css` 하나. 파일을 더 쪼개지 않는다.
- 시작 후보: 요약 카드, 접는 줄(미션 한 줄), 라벨 칩, 안내 상자, 코드 블록. 그리고 `el()` · `esc()` 한 벌.
  후보는 이 화면에서 실제로 두 번 이상 쓰이는 것만 확정한다 (한 번만 쓰면 뽑지 않는다).
- 이름은 기존 클래스(`.chip` `.mark` 등)와 겹치지 않게 접두사를 붙인다(`k-`). 단 `.k-data` 등 블록 종류 클래스가 이미 `k-` 를 쓰므로
  접두사는 구현 때 겹치지 않는 것으로 정한다.
- 전·후 비교는 `docs/superpowers/specs/` 아래에 표로 남기고, 이전 코드는 git 기록으로 확인할 수 있게 한다
  (저장소에 옛 코드를 복사해 두지 않는다).
- 접는 줄은 `<details>` 를 쓴다 — 브라우저가 이미 하는 일이고 키보드 · 스크린리더가 공짜다.

## 제 판단 2 (검토자 질문에 대한 답 — 사용자 확인 전)

- **테스트 선택자:** `.d-*` · `#detail` 안 id 는 새 구조에 맞게 바꿔도 된다. 선택자를 쓰는 테스트(`smoke.js` `robust.js` playwright)는 같은 커밋에서 같이 고친다. 호환용 옛 클래스는 남기지 않는다. 테스트가 확인하던 **행동**(자유 입력이 상세에 올라간다, 가로 스크롤 없음, 금지 단어 없음)은 그대로 지킨다.
- **`el` · `esc`:** 이번 범위에서 `teacher.js` 의 것을 `CC.kit` 것으로 갈아 끼운다. 다른 5개 파일은 후보 목록에만 올린다. `teacher.html` 에서 `kit.js` 를 `teacher.js` 앞에 싣는다. 전·후 지표의 "중복 정의 수"는 7→6(kit 로 합치고 teacher 쪽 제거)으로 센다.
- **글자 크기:** `#detail` 안에만 적용한다. 명단 · 알림 · 다른 화면은 이번에 키우지 않는다.

## 빌더에게 맡기는 것

- 요약 카드의 "잘한 점"에 어떤 사실을 올릴지 (알림 문장 `CC.alerts` 에 이미 있는 사실 문장 재사용을 먼저 검토).
- 펼침 줄 안의 순서 · 세부 배치.
- 테스트 추가 방식 (기존 `test/smoke.js` · `robust.js` · playwright 에 맞춘다).
- 전·후 숫자를 어떻게 잴지 (줄 수는 `wc`, 중복 정의 수는 `grep`).
