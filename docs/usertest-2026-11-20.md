# 학생 2명 사용 테스트 — 화면 보기 · AI 생성 문제 이해 (2026-11-20)

학생 2명에게 테스트했고, 나온 말은 두 가지다. 아래 따옴표는 사람이 전한 말을 그대로 옮겼다.
학생 이름 · 학년 · 테스트한 미션은 이 문서에 적지 않았다(받지 않았다).

1. **"화면 보기가 힘들다"**
2. **"AI 로 생성한 문제 이해가 잘 안된다"**

상태: **작업 중.** 이 문서는 들은 것과 지금까지 한 것 · 할 것만 적는다. 원인은 아직 확인하지 않았다 — 추측은 적지 않는다.

## 1. 화면 보기

같은 날 선생님 쪽에서도 같은 말이 먼저 나왔다 — "보기 힘들어서 기다리는 동안 제대로 도는지 모르겠다"(생성 진행),
"학생 결과를 보는 화면 · AI 로 문제를 생성하는 과정에서 결과를 바로 확인하기도 어렵고 보기에도 안 좋다".

| 한 것 | 어디 |
|---|---|
| 생성 진행 칸을 화면 안으로, 상태는 글자('지금' · '끝남' · '멈춤'), 대비 WCAG AA | [tomchaccom/KOMPAS#43](https://github.com/tomchaccom/KOMPAS/pull/43) (머지) |
| 밝은 · 어두운 화면 버튼(학생 화면 포함) | 같은 PR |
| 선생님 화면 두 곳 시안 — 학생 결과 · AI 생성 결과, 개선안 + 압축형 | 디자인 캔버스(사람 계정, 공유 전) |

시안의 방향(선생님 화면):
- **학생 결과**: 위에 요약 막대 한 줄(먼저 물어볼 것 · 나침반 · 선생님 한마디), 아래는 미션 하나 = 한 줄
  (단계 · 고른 성공 조건 · 반례 · 튜터 · 마지막). 12항목 표는 펼친 미션 안으로 넣어 한 번에 한 미션만 보인다.
  [tomchaccom/KOMPAS#41](https://github.com/tomchaccom/KOMPAS/pull/41)(학생 상세 A안, `main` 과 충돌)과 방향이 같다 — 살릴지 새로 할지 정한다.
- **AI 생성 결과**: 맨 위 한 줄에 결과와 버튼(학생에게 내기 · 다시 만들기 · 버리기). 왼쪽 학생 화면 미리 보기,
  오른쪽 선생님만 보는 확인 거리(자료별 답 · 진짜/함정 · 설계 카드 · 검수 기록). 입력창은 '고치기' 를 눌렀을 때만 연다.

할 것:
- [ ] 학생들이 말한 "화면" 이 어느 화면인지(학생 미션 화면 · 내 기록 · 튜터) 확인한다 — 위 시안은 선생님 화면이다.
- [ ] 확인한 학생 화면을 같은 방법(실제 폭에서 찍기 → 문제 짚기 → 시안)으로 본다.
- [ ] 시안 중 하나를 골라 코드에 옮긴다.

## 2. AI 생성 문제 이해

생성 문제 문장에는 이미 규칙이 있다 — `api/_schema.py`: 개발 용어 금지("중1이 읽는 문장이다"),
덧붙인 설명 없이 한 번에 읽히는 문장, 존댓말. 검수(`api/_review.py`)는 학생에게 내기 전에 한 번 더 본다.
규칙을 통과한 문장도 학생에게는 이해가 안 됐다는 것이 이번에 들은 것이다.

할 것:
- [ ] 학생이 이해 못 한 문제 원문을 받는다(상황 · 요청 · 자료). 없으면 같은 수업 · 핵심으로 다시 만들어 학생에게 다시 보인다.
- [ ] 어느 부분에서 막혔는지 학생 말로 받는다 — 상황 문장 · 요청 · 자료 꼴(`[1500, 800]` 같은 리스트) · 성공 조건 보기 중.
- [ ] 막힌 곳이 규칙으로 잡히는 종류면 `api/_schema.py` 검사 + `test/test_missionguard.py` 에, 아니면 생성 · 검수 프롬프트에 반영한다.
      브리프를 쉽게 만들되 **방법을 적지 않는다**(CLAUDE.md "브리프는 모호하게") — 쉬운 말과 정답 공개를 가른다.

## 지키는 것

- 쉽게 만든다고 판단을 대신하지 않는다: 힌트 · 다음 블록 추천 · 방법 체크리스트는 넣지 않는다.
- 학생 화면 문구 규칙(존댓말 · 질문 80자 · 판정하지 않기)은 그대로다.
